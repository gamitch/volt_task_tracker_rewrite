## 2. The rules that now govern dispatch

**Constitution item 28** — work comes from Linear's `Todo`. Claim *before opening a file*, then
re-read to confirm (Linear has no compare-and-set, so two agents can otherwise both claim). A
`tier/unreviewed` issue may not enter `In Progress` until it is tiered. On completion, `In Review`
plus a `Linear-Issue:` trailer. **Identity is the `tier/*` label**, not the title — a skill-filed
finding has no `Tnnn` and is still ours.

**Constitution item 29** — the ledger is frozen, the number blocks are retired, and the git-side
record is generated rather than maintained.

**`AGENTS.md`** carries both as its first section, because that is the file agents demonstrably
read.

---

## 3. Why ClickUp was abandoned

Not preference. Two limits, both undocumented and both discovered the hard way:

- **A cumulative daily request budget of roughly 30–50 calls.** Two ~22 hour lockouts. The first was
  blamed on burst shape; the second happened with strictly sequential calls, which **disproved that
  diagnosis** — it is volume per day, not concurrency.
- **A custom-field cap.** Setting `Tier` returned *"Custom field usages exceeded for your plan"* —
  and constitution item 26 dispatches on Tier.

A third problem was pure cost: the CSV importer **escaped Markdown at the character level**, storing
`\*\*bold\*\*` and `v\_student\_participation`. Repairing 24 descriptions consumed most of a daily
budget.

**Linear, measured:** 2,500 requests/hour (neither the 5,000 its own docs claim nor the 1,500
third-party sources report — the number came from response headers), remaining quota visible on
every response, 250 *active* issues on the free plan with **archived exempt**, and Markdown that
survives a torture test intact.

## 4. What the migration actually found

This is the part worth keeping. The tracker change was the smaller half.

**`T063b` — merged, tested, live work with no ledger row at all.** `manifest.ts`, `teardown.ts` and
`manifest.test.ts` are on `main`, landed in PR #53, 31 tests green — and there was no row and no
verification-log entry. Constitution item 24's own failure shape applied to item 24. Found by
cross-referencing every `Tnnn` mentioned anywhere in `docs/` against the ledger's rows.

**`WORKFLOWS.md` had been miscounting for weeks.** It claimed 40 open rows; the ledger yielded 50.
Every comparable workflow disagreed. This confirmed T512's premise with numbers.

**Eleven rows were closed in a column no parser reads.** On 2026-08-04/05 a session recorded closures
by writing `CLOSED …` into the **Epic** cell while `Status` still read `Filed`. Perfectly readable to
a human; invisible to the migration. All eleven became live issues, and an agent picked one up and
worked a row superseded four days earlier.

**PR #118's four UI bugs existed only in a PR body.** None had a row; `events.created_by` appeared
zero times in the project's records. Now `T808`, `T809`, `T615`, `T616` — each re-verified against
the tree, and one had been reported against a component path that does not exist.

## 5. Decisions, with their reasoning

**Labels, not custom fields.** Linear label *groups* are mutually exclusive and carry descriptions —
dropdown semantics without a custom field. `tier/*`, `area/*`, `gate/*`, `provenance/*`, `escalated`.

**`tier/unreviewed`, not a defaulted `standard`.** The owner proposed defaulting blank tiers to
`standard`. Refused, because a defaulted `standard` is **indistinguishable from a judged one** — the
placeholder-default class behind T151, T155, T158, T159, T170, T176, T181 and T407, and the reason
T172 exists. Also mechanical: only HEAVY runs `checker-premise`, so a defaulted `standard` would
never reach the validation the proposal relied on. **Validated in practice** — the first dispatched
agent had to judge the tier, and judged it correctly.

**Area as a label, not a Linear Project.** 83% of rows (245 of 301) predate the W-block scheme
entirely and would have sat in no project. `WORKFLOWS.md` also says a number block is *"a
collision-avoidance reservation, not an ownership claim"* — `T509` sits in W2's range and is W4's
work — so deriving projects from ids would misfile silently. And a Project has dates and a progress
bar; "Run a meeting" is a permanent area with no end.

**`Attempts` is not `estimate`.** `estimate` means complexity in Linear and drives velocity and
burndown. Attempt counts there would corrupt Linear's own charts.

**`Worker`/`Checker` are not `assigneeId`.** They are agent identities, not workspace members, and
the accountable human is the owner for every row. `IssueCreateInput.delegateId` — "the agent user to
delegate to" — is the correct future home if agents are ever registered.

**Migrate all 301 rows, not the 50 open ones.** Archived issues are exempt from the 250 cap, so the
full history fits with ~46 active.

**Export both JSON and Markdown, generate both.** The distinction that matters is not format but
**maintained versus generated** — every ledger failure above came from hand-maintenance, and a
generated file cannot put a closure in the wrong column.

## 6. Mistakes made in this session

Recorded because the pattern is more useful than the list.

| Mistake | How it was caught |
|---|---|
| Row regex `^\|\s*T\d+\s*\|` silently dropped 7 suffixed ids (`T002a`, `T073b1`) | the owner's count disagreed |
| Offered two already-closed rows as test candidates | the agent worked one before anyone noticed |
| `git checkout main` + `checkout -B` orphaned 3 commits, then force-pushed over them | noticed the branch was 2 commits, not 5 |
| A string replace ran against a file where its anchor no longer existed — **changed nothing, reported success** | grep for the expected content |
| Export query cost 22,861 against a 10,000 complexity cap I had documented that morning | first real run |
| The count cross-check had no pagination — would have compared 301 to one page and **aborted for the wrong reason** | reading it while fixing the above |
| `provenance` label group specified in the plan, omitted from the specs | filer dry-run against live data |
| Committed a lint error twice (`API`, `gql` left unused after removing their callers) | `npm run lint` |
| `T1300` filed as `tier/standard` because its own prose said "expect FAST or STANDARD" | checking the payload after filing |
| `AGENTS.md` orientation order still claimed at step 4, contradicting item 28 | watching an agent take 9 commands to find its issue |
| A commit message *explaining* the skip-CI marker contained the literal token — and silently skipped CI on its own PR | PR #130 showed **zero** check runs |

**The recurring shape: a silent no-op that looks like success.** A too-strict regex returns a smaller
plausible number. A replace with no anchor changes nothing and exits 0. A guard that never fires is
indistinguishable from a guard that works. Three separate defenses now exist for this — assert the
expected count, abort when an edit anchor is missing, and prove a guard by making it fire.

## 6a. A correction to T808, made by the agent that worked it

**The row I filed states something false, and `GAM-303` still carries it.** T808 says *"The coach
dashboard shows `4.0` for the same student."* Measured by the agent working it, and confirmed
independently: `CoachHome.tsx:2050` prints

```
`${row.confirmedHours}h confirmed + ${row.plannedHours}h planned = ${totalHours}h …`
```

`totalHours` is rounded; **`row.confirmedHours` and `row.plannedHours` are raw**, identical to
`StudentHome.tsx:1485`. The coach's *home* dashboard has the same bug. The `4.0` is the
**Reports → Hours tab**.

**Corrected again, by the same agent, and it matters for the fix.** This document first cited
`HoursTab.tsx:605`. That line is inside `Array.from(byTeam.values()).map(group => …)` reducing over
`group.rows` — it rounds **team subtotals**. The per-student `4.0` comes from `renderHoursCell` at
**`HoursTab.tsx:1017`**, which uses **`.toFixed(1)`**, not `round1`.

The distinction is the whole point of `GAM-308`: `round1` renders `4`, `.toFixed(1)` renders `4.0`.
Fixing `CoachHome` with `round1` would kill the float and leave a smaller version of the same
cross-surface mismatch. Whoever takes `GAM-308` needs `:1017`, not `:605`.

**The real inconsistency is reports-vs-home, not coach-vs-student.**

How it happened: PR #118 reported the comparison, and when filing T808 I re-verified the StudentHome
half and **took the comparison on trust**. That is the same failure this project keeps recording —
inheriting a premise instead of measuring it — committed while writing a row whose own text warns
about it. The e2e-personas skill now requires a `verifiedBy` field per finding for exactly this
reason; had the original finding carried one, the comparison would have been marked as unverified.

Filed as `GAM-308` rather than folded in, correctly: `CoachHome.tsx` is outside T808's stated scope
(item 20).

**Outstanding:** `GAM-303`'s description still asserts the false comparison and should be corrected
in Linear. The frozen ledger's row is left as-is — it records what was believed on 2026-08-09, and
rewriting history is not the same as correcting the record.

## 7. Tooling built

| Script | Purpose |
|---|---|
| `scripts/linear-migrate.mjs` | one-time migration; idempotent, checkpointed, dry-run default. Cross-column guard: a row whose `Status` says open while another cell says CLOSED is **withheld**, never reclassified |
| `scripts/linear-export.mjs` | the git-side backup. `--check` fails when stale (proven both directions). Cross-checks its own pagination and refuses to write a partial |
| `scripts/linear-file-findings.mjs` | files skill findings to `Backlog`. Dry-run default, dedupes on `Finding-Key`, applies `tier/unreviewed`, aborts rather than inventing a label |
| `scripts/linear/client.mjs` | shared GraphQL client; names the complexity failure rather than surfacing a bare number |
| `.claude/skills/e2e-personas/SKILL.md` | now emits findings as data and **fails a run with unfiled findings** |
| `docs/swarm/active/FINDINGS-PIPELINE.md` | the findings schema and the pipeline design |

Direct GraphQL rather than the Linear MCP, deliberately: MCP hides the rate-limit headers, exposes no
delete for rollback, cannot batch, and cannot be read before it runs.

## 8. Outstanding

1. ~~**`--check` is not wired into CI**~~ — **done**, PR #129. `.github/workflows/linear-export.yml`
   exports on push to `main`, daily at 06:00 UTC, and on demand; it commits the two files when they
   move and asserts `--check` against what it just wrote. Item 29c was **corrected rather than
   implemented** — its original "let CI enforce it" would have failed every task PR, because
   claiming an issue moves it `Todo → In Progress` and makes the committed export stale by
   definition. Heal, do not gate.

   Its first live run proved itself on real data: `exported 309 issues (242 archived) in 16
   requests`, committed `ed2f7a1`, `--check` green — and the whole diff beyond timestamps was
   `GAM-309` moving `Backlog → In Progress` with `tier/unreviewed → tier/standard`. That is an
   agent claiming an issue under item 28, which is *precisely* the state change a `--check` gate
   would have failed on.

   **One caveat, recorded because this project keeps meeting it.** The job is documented as safe
   from self-retriggering because of `paths-ignore` on the two export files. It did not retrigger —
   but the bot's commit message also carries `[skip ci]`, which suppresses every workflow on that
   push regardless of paths. **Two mechanisms, either sufficient, neither observed firing alone.**
   Harmless, but it is the recurring shape from §6: a guard that never fires is indistinguishable
   from a guard that works. Do not remove either believing the other is what holds.

   **And a live trap that this very paragraph sprang.** GitHub scans the *whole* commit message for
   the skip-CI marker, so a commit that merely **writes about** it skips CI itself. The first
   attempt at this document did exactly that and its PR ran **zero** checks. `ci.yml` has no path
   filters, so silence means suppressed, not "nothing to run" — when a PR shows no checks at all,
   grep the commit message before assuming it is docs-only. Refer to the marker in prose, never
   verbatim.
